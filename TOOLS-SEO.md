# Elysium Tools deployment

Elysium Tools runs at https://tools.elysiumdr.eu/ through the Elysium Cloudflare Worker. English, Spanish and Portuguese pages are generated from `scripts/tools/content.mjs` with `node scripts/build-tools.mjs`. Run the same command with `--check` to verify the generated files. The former catalogue input is retained under `scripts/tools/legacy/content.json` for reference.

The Worker routes `/api/tools/*` to the separate `elysium-tools` Cloud Run service. The tools are for Elysium clients and team: signing in with an existing Elysium account (a CRM `members/{uid}` profile, or a team identity) opens them at once, with no request, separate license or manual approval, and the subdomain creates no accounts. The public pages describe the tools and only offer sign-in; they contain no operational workspace. The Worker delivers that workspace only after checking the account with `/api/tools-license/access` (the route keeps its old name). Processing and file downloads repeat that check, and a deactivated CRM profile is cut off. Turnstile, gateway secrets, origin validation and per-visitor limits remain enabled. A secure HttpOnly session cookie is used by Tools. The administrator routes retain Firebase authentication. Configuration and deployment instructions are maintained in `backend/tools/README.md` and `CLAUDE.md`.

The catalogue, public modules and backend declare the same supported platforms and limits. YouTube is not a public promise: from Google Cloud it asks the server to prove it is not a bot, so it downloads only with the YouTube account each person connects in the tool, and the pages say exactly that (no YouTube landing page). PDF page editing and ID-card PDF creation run in the browser; PDF-to-Word conversion runs in Cloud Run. Automated tests use fixture engines and do not establish live platform compatibility.

Validate with `node --test scripts/*.test.mjs`, `npm test --prefix backend` and `npm test --prefix backend/tools`. Local HTTP tests require permission to bind ports. Confirm the production health endpoints, public configuration, page status, redirects and generated discovery documents after deployment. Search indexing is independent of publication and remains subject to the search engines.
